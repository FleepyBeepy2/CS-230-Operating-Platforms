# CS-230-Operating-Platforms

Portfolio for 8-2



Briefly summarize The Gaming Room client and their software requirements. Who was the client? What type of software did they want you to design?

The Gaming Room is a company who requested their application to be extended to other platforms. They wanted me to design software that could support clients from every platform to utilize the Draw It or Lose It server.





What did you do particularly well in developing this documentation?



For me, it was identifying the requirements for the application. Each requirement explains, both in detail and simplicity, the features The Gaming Room wanted me to implement into the software.







What about the process of working through a design document did you find helpful when developing the code?



I found that listing out the requirements for the system helps a lot when planning the structure of the code. Knowing what features are needed and their constraints gives a good visual on what variables and methods are needed to develop that logic.







If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?



I would choose the recommendations. The recommendations portion of the document is only a couple sentences with not that much detail of what could be the best option for developing the system. Each portion of the recommendation section could be improved with one or two more sentences that go into a bit more depth.







How did you interpret the user’s needs and implement them into your software design? Why is it so important to consider the user’s needs when designing?



By evaluating what the system should do and how the server should react to it, one can determine that the server reacting to a specific action would have to be caused by the user. For example, the system needs to be able to connect multiple users at a time to a single instance of the game. To do so, the server reacts by receiving multiple HTTP requests to connect to the server. Those requests have to come from the user. Those requests could also come from any platform. It’s important to consider the needs of the user because they’re the ones who are going to be using it. If the product isn’t user friendly then no one is going to want to use it.







How did you approach designing software? What techniques or strategies would you use in the future to analyze and design a similar software application?



I approached it by considering both the client side and the server side as well as the hardware needed to support the server. I would use the same strategies that the template used. I would list out all of the functional requirements, design requirements, and consider which platform or hardware would be best suited given the limitations from the customer and the limitations from within the work environment.
